## §1 Объём и границы

все витрины/статы koilog. Задача — пометить их флагом `is_foreign` (прецедент

участвует ни в `recompute_metrics`, ни в каком-либо health-запросе (осознанное решение,
доказательство пренебрежимости — в §5).

**Фенсы (авто-стоп при диффе):**

- `recompute_metrics` / `_COUNTS_SQL` / `_KOI_UPDATE` — **не трогать** (на `rm_session`/`koi`

## §3 Решения D1–D5

### D1 — точка вычисления флага: `_finalize`, рядом с `is_gravitron` (etl.py:861–868)

- `_finalize` — **единая** точка финализации, которую зовут **обе** ветки загрузки
  (`load_journal` → `yield _finalize(...)` строка 1291; `load_workoutreport` → строка 1577).
  Это и есть защита от «флаг теряется при перезагрузке только отчёта» (Task 105: Диана —
  `source='report'`, отчёт перегружается `DELETE`+`INSERT`): предикат пересчитывается из
  источника при каждом построении строки, в обеих ветках.
- `is_foreign` зависит **только** от уже лежащих на `SetRow` полей `program`/`workout_name`
  и **не** зависит от веса тела — поэтому его место ровно там, где `is_outlier`/`is_gravitron`,
  а **не** в пост-проходе `_refill_bodyweight` (тот пересчитывает весозависимые поля).
- **Морфология (по паттерну T1):** `CREATE TABLE` (в блоке 208–210, после `is_gravitron`),
  `ADDED_COLUMNS` (233–238), поле dataclass `is_foreign: int = 0` (382–384), `as_tuple`
  (400–410), `_COLUMNS` (413–419), `'?' * 30` → `'?' * 31` (421–424). Миграция существующей
  базы — автоматически через `_add_missing_columns` (473–478) при следующем `load`/`refresh`.

### D1-бис — канонический vs защитный предикат

- **Канонический:** `program = 'Диана'`.
- **Защитный:** `workout_name LIKE '%Диана%'` (эквивалентен на текущих данных 63↔63, 0/0).
- `is_foreign = 1` если канонический **или** защитный. Зафиксировано: канонический — первым,
  защитный — как страховка от переименования поля `program` в другой выгрузке.

### D2 — форма фильтра витрин: литералы `AND is_foreign = 0`

- Прецедент — литералы `is_outlier = 0` в каждом запросе (`stats.py:230/488/978/1397`,
  `muscle_load.py:209`). Общий фрагмент/CTE-хелпер **не вводим**.
- `_BEST_LAST_SQL` фильтруется чок-пойнтом — CTE `days` (`WHERE rm IS NOT NULL AND
  is_foreign = 0`, строка 248–249); подзапросы 310–334 берут ключи (`session_id`/`date`)
  из уже отфильтрованного слоя и чужих сессий не видят транзитивно.
- Границы окна (`MAX(date)`: 512/547/1427/316/456) — фильтр **не меняет результат** (Диана
  2021 < MAX 2026), но на `456`/`752` ставим по требованию D5; остальные `MAX(date)`
  оставляем без фильтра по прецеденту `is_outlier` (у `is_outlier` тоже нет фильтра на
  границах окна).

### D3 — `estimate_bodyweight` / вес тела по годам: **не трогать**

Доказательство пренебрежимости (замер, §2): у «Дианы» нет ни одной строки с
`weight_mode='total_bodyweight'` **и** `exercise IN BODYWEIGHT_SOURCES` (пусто). Её
total_bodyweight-строки — «Подтягивания широким хватом за голову», этого имени в
`BODYWEIGHT_SOURCES` нет. Вклад Дианы в оценку веса тела = **ровно 0**, фильтр или его
отсутствие результат не меняют.

### D4 — диагностика/аудит: **без фильтра** (прецедент `exercise_audit`/`explain`)

Список (заморожен): `outlier_summary`, `outlier_detail`, `outlier_totals`,
`reinterpreted_as_seconds`, `unmapped_exercises`, `timed_suspects`, `weight_anomalies`,
`implied_bodyweight`, `summary`, `exercise_audit`, `stats.explain_sets`, `export_csv`.
Разбор показывает сырые счётчики — выбросы Дианы (6) и её 63 сета там видны как есть.

### D5 — cli-витрины: **фильтровать обе**

- `_stock_gaps` (752): без фильтра веса Дианы (напр. «Разгибание руки с гантелью из-за
  головы») попадают в список «веса, которых нет в инвентаре». Фильтр — `AND is_foreign = 0`.
- `_latest_year` (456): `MAX(date)` Дианы 2021 < 2026, результат не меняется; фильтр ставим
  для единого правила «все витрины коилога фильтруют».
- Замера «не фильтровать» не требуется — измеренное влияние ненулевое (чужие веса в
  `_stock_gaps`), основание «не фильтровать» отсутствует.
