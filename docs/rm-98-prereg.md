## §1 Объём и границы

В отличие от DN-102 (append-only маркер `is_foreign`, физического удаления нет), RM-98 —
**переопределение хранимой метрики**: `weight` строк `weight_mode='vest_only'` сейчас равен
`сырьё + тело` (k=1.0), а должен стать `E = 0.6·тело + добавка` для семейства отжиманий и
`1.0·тело + добавка` для прочих vest_only (рекомендация R2/R3). От этого зависят `rm`,
`rm_session`, `rm_ma_30d`, `koi` (пересчёт) и все витрины, читающие эти колонки.

**Принятые следствия (зафиксированы как часть скоупа):**
1. **Пересчёт живой базы** — `load`/`refresh` вызовет `_refill_bodyweight` +
   `recompute_metrics`; числа в витринах сдвинутся (см. §2.4–2.6).
2. **Таблица «до/после»** обязательна в кодовом коммите (§7).
3. **Откатная копия** `sql/training.db.pre-rm98.db` снимается **до** первого применения и
   регистрируется в `docs/housekeeping.md` (прецедент K2/K3 из HK-107); sha256 живой базы
   фиксируется до и после, контроль бит-в-бит для нетронутых путей.
4. Семантика истории (а)–(г) — **восстановленная реконструкция, подтверждённая лидом на
   гейте**; первоисточника в git нет, поэтому как дословная цитата не оформляется (см. R1).

**Чего НЕ трогаем (фенсы §6):** `setstate/gate/digest` формулы, `estimate_bodyweight`/
`BODYWEIGHT_SOURCES`, `total_bodyweight`-строки, `ml_labels`, порог бюджета; `ml_score`
остаётся append-only (новая спека через `SPEC_VERSION`, механика винтажей N-2 уже есть).

### §2.7 Калибровка «отжимания vs жим» (критерий приёмки)

E-1RM отжиманий (reps ≤ 12, лучший подход года) против 1RM жима (штанги лёжа / штанги /
гантелей лёжа — лучший года):

| год | отжимания @k=0.6 | жим | отношение |
|---|---|---|---|
| 2020 | 59.6 | 84.0 | 0.71 |
| 2021 | 58.8 | 86.4 | 0.68 |
| 2024 | 87.6 | 77.8 | 1.13 |
| 2025 | 72.0 | 74.8 | 0.96 |
| 2026 | 77.0 | 74.6 | 1.03 |

**Медиана 0.96** (min 0.68, max 1.13). Sweep по k: 0.5 → медиана 0.84; **0.6 → 0.96**;
0.7 → 1.09. Значит `k = 0.6` — ближайший к единице из трёх круглых кандидатов. Снаружи
семейства 0.6 ломает правдоподобие: Подтягивания 111.3 → 66.8, Брусья 146.1 → 87.7,
Приседания (reps≤12) 99.4 → 59.6 < собственного тела 69.0 — поэтому скала **по семействам**.

- **Приседания** — единственный не-absolute «присед»: 32 строки, только 2020, reps 10–20,

- **`estimate_bodyweight`** читает `weight` только для `total_bodyweight`-источников

  трогается → обратная связь невозможна; при любом k≠1 для TB надо переключать чтение на

- **`default_exercise` = «Жим гантелей лёжа»** (absolute, `base_weight 64`) → дайджест-рампа

  таблица до/после в §2.3/§2.4 измеряет чистый эффект RM-98.

## §4 Развилки (R1–R7), с рекомендациями

### R1 — текст (а)–(г) «семантики истории» (подтверждено лидом на гейте)

Скоуп «вариант B с семантикой истории (а)–(г)» — **восстановленная реконструкция**:
первоисточника в git нет, поэтому текст ниже — не дословная цитата, а реконструкция,
подтверждённая лидом на гейте:

- **(а)** `vest_only` с добавкой D: `E = 0.6·тело + D`, `added = D`, `rm = Brzycki(E, reps)`.
- **(б)** `vest_only` без добавки (0/NULL): `E = 0.6·тело`, `added = 0`, 1RM появляется.
- **(в)** `total_bodyweight`: вес как записан, `added = weight − тело`, k=1.0 — не меняется.
- **(г)** `absolute`: не трогаем.

**Решение (гейт):** «вариант B» = **сценарий C** («E только для vest_only»). Сценарии (рабочий
срез, база 990 756 кг): A «vest_only, только строки с rm» −5.38 %; **C «vest_only + E на
нули» +0.76 %**; B «все не-absolute, только с rm» −36.99 %; D «все не-absolute + E на нули»
−31.76 %. D/B ломают `estimate_bodyweight` (обратная связь) и дают −32…−37 % тонаджа —
несовместимо с «эффективной» нагрузкой, отклонены.

### R2 — границы k (рекомендация: версионная таблица по семействам)

`k = 0.6` только для **семейства отжиманий** (Отжимания, Отжимания от скамьи, Отжимания от
пола, Отжимания трицепсами спиной к скамье), `1.0` — для остальных vest_only (Приседания).
Обоснование — §2.7 (медиана внутри семейства 0.96; снаружи 0.6 даёт 1RM ниже собственного
веса). Хранить как таблицу `эффективная доля` рядом с `resolve_bodyweight` (не display):
именная `frozenset` + дефолт `1.0`, со ссылкой на §5. Альтернативы: 0.6 для всех vest_only
(отклонено — Приседания 99.4 → 59.6 < 69), единый k без семейств (отклонено — см. §2.7).

### R2b — ноль/отсутствие добавки (рекомендация: **A — E только для vest_only**)

`weight = 0/NULL` сегодня → `None` (нет 1RM). Рекомендация **A**: у `vest_only` пустота
означает «добавки нет» → `E = 0.6·тело`, `added = 0`, 1RM **появляется** (это 153 строки:
109 «Отжимания», 32 «Приседания», …). `total_bodyweight` с пустотой добавки **остаётся
`None`** (добавку нельзя вывести из веса тела — фенс обратной связи). Альтернатива (B —
пустота и для TB даёт E) отклонена: она переписывает записанный вес и ломает
`estimate_bodyweight`.

### R3 — жилет для приседа/становой (рекомендация: **k=1.0**)

Приседания получают `E = 1.0·69 = 69` → 1RM 146.1 (20 повт). Становая — `ABSOLUTE`, 0
BW-строк, k неприменим. Рекомендация: **не вводить жилет-коэффициент** для приседа (нет
жилета в данных: `added` = 0/NULL), k=1.0; риск «барбельной рампы из приседа» закрывается
гардом R7, а не специальным k. (Решение заказчика фиксируется явно; отклонение от k=1.0 для
приседа — отдельный пререг, без него не делать.)

### R4 — точка перезаписи `weight := E` (рекомендация: **в `resolve_bodyweight`, провенанс сохранён**)

`raw_weight` уже фиксируется в `_finalize` **до** всякой математики тела, `added_weight`
хранится отдельно → перезапись `weight := E` ничего не теряет. Единая правка в
`resolve_bodyweight` автоматически покрывает и новые загрузки (`_finalize`), и историю

## §5 Калибровочная петля и версионная таблица k

| v1 (RM-98) | отжимания | 0.6 | 0.96 | 2026-11-03 | §2.7 (2020/21/24/25/26) |

Переносимые в код значения: семейство отжиманий `0.6`, дефолт `1.0`; числа таблицы — в
код-комментарии со ссылкой на этот раздел (прецедент NU-138: ссылки на docs, не маркеры).
