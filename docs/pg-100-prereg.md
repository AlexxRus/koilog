## §1 Объём и границы

PG-100 описывает **структуру тренировочных программ по факту журнала**: какие дни-шаблоны
повторяются, из чего они состоят, в каком порядке сменяют друг друга и насколько дни
окна попадают в библиотеку шаблонов своей эры. Это **описательная витрина**, не оценка
качества программы и не рекомендация.

**Входит:**

- модуль `koilog/program_patterns.py` (display-only): сигнатуры дня, библиотека шаблонов,
  состав, переходы (цикл), таблица эр, приверженность;
- секция `koilog.ipynb` («Паттерны программ») — markdown + один code-блок;
- тесты (детерминизм, границы, фенсы, свойства на живой базе);
- отображение кардио-флага отдельной колонкой (не часть сигнатуры).

**Не входит (заведомо):**

- нагрузка, тоннаж, 1RM, КОИ, доли мышц — это 4.14 (`muscle_load`), PW-99 (`muscle_share`),
  RW-98 (`work_arc`); здесь их нет даже как колонок;
- кластеризация/ML, предсказание следующего дня, «оценка оптимальности» сплита;
- решения: `state`, `retrain`, `gate`, `digest`, `score`, `ml` — не трогаются и модуль не импортируют;
- правка `sets`, `taxonomy`, `workout_name` (нормализация имён — только на слое отображения);
- новые пороги решений; новых констант-порогов, кроме отображательных (K, окно эры), нет;
- сравнение с литературой/чужими программами; «правильность» сплита не оценивается.

**Display-only:** как 4.14/RW-98 — модуль входит только в витрину; ни один решающий
модуль его не импортирует (импорт-фенс тестом).

## §2 Единица и уровни сигнатуры

**Единица — тренировочный день** (дата с ≥1 рабочим подходом), а не сессия: в живой базе
**643 из 1 400** дней имеют больше одной `session_id` (силовая + кардио — обычная картина,
55.8 % дней содержат кардио-строку). Сессия разрезала бы день на несопоставимые части.

**Пул:** `sets` с `date IS NOT NULL AND is_warmup = 0 AND skipped = 0 AND is_outlier = 0
AND is_foreign = 0` (канон фильтров 4.14/DN-102). «Разминка» — не упражнение шаблона.

**Кардио** (`taxonomy.group_of(...).name == "КАРДИО"`) **исключается из силовой сигнатуры**
и показывается отдельным флагом `+кардио` (иначе «Бег» делает шаблоном половину истории).

**Четыре уровня сигнатуры** (все замерены, §4):

| уровень | что | distinct (2026 / всё время) | top-5 (2026 / всё время) |
|---|---|---|---|
| **L1 имена тренировок** (`workout_name`) | `("1. Присед",)` … `("5. Руки",)` | **5 / 100** | **100 % / 35.1 %** |
| L2 группы таксономии | `("ДЕЛЬТЫ","ПРИСЕДАНИЯ",…)` | 8 / 273 | 87.8 % / 19.8 % |
| L3 набор упражнений (порядок не важен) | `{Приседания с гантелями, …}` | 7 / 343 | 95.1 % / 21.9 % |
| L3o последовательность упражнений | порядок важен | 8 / 377 | 87.8 % / 18.8 % |

**Рекомендация:** канон — **L1** (имена тренировок): единственный уровень со 100 % покрытием
дней и 1:1 с задуманными типами дня в текущей эре; L2/L3 — производные колонки состава и
устойчивости к переименованиям.

## §3 Шаблоны v1 (контракт)

- **Шаблон** = L1-сигнатура дня + состав (частота упражнений) + число дней + первое упражнение
  (атрибут порядка).
- **Библиотека эры**: топ-K сигнатур по числу дней; **K = минимум, покрывающий ≥ 90 % дней
  эры, кап 10**; ничьи — по убыванию числа дней, затем по имени (лексикографически).
  Дни вне библиотеки — «прочее» с перечнем сигнатур (без домысливания).
- **Эры v1 — календарные окна** (год) + карточка «текущее окно 90 дней» от `MAX(date)`.
  Автоматических чейнджпоинтов в v1 нет (§10 форк PG-F4); границы — описательные, не причинные.
- **Переход (цикл)** считается только между соседними тренировочными днями одной эры;
  разрыв в календаре **> 14 дней** переходом не считается (простой/болезнь — не смена
  программы; порог 14 — витринный, не решающий; обоснование: `GATE_SILENCE_DAYS = 14` уже
  используется как граница «одного кластера» в D10).
- **Приверженность** = доля дней окна, чья L1-сигнатура входит в библиотеку эры;
  показывается с числителем/знаменателем и списком «новых» дней.
- **Нормализация имён — никакой:** имя берётся как хранится (W7/D9: вендорский фид — канон).
  Варианты «Gym / 1» и «1. Присед» — разные шаблоны, даже если состав совпадает; это предел
  метода, названный в §11.

## §5 Цикл и кадентность

**Текущая эра (2026), L1-переходы** — доминирует пятидневный цикл:

| от → к | раз |
|---|---|
| `1. Присед` → `2. Жим` | 34 |
| `2. Жим` → `3. Становая` | 33 |
| `3. Становая` → `4. Тяги` | 31 |
| `4. Тяги` → `5. Руки` | 29 |
| `5. Руки` → `1. Присед` | 29 |
| `1. Присед` → `1. Присед` | 2 |
| `3. Становая` → `1. Присед` | 2 |
| `4. Тяги` → `1. Присед` | 2 |

- **156 из 162** переходов 2026 — по кольцу 1→2→3→4→5→1 = **96.3 %**; остальное — повторы
  и возвраты (дни вне режима, ручные вставки). Знаменатель 162, а не 163: разрыв
  `2026-02-09` → `2026-03-12` (31 день, оба дня `1. Присед`) по §3 переходом не считается.
- **Это не календарный 5-дневный цикл:** повтор сигнатуры через 5 дней — 4.1 %, через 4 — 5.8 %.
- **Кадентность недельная:** повтор сигнатуры через 7 дней — 71.4 % за всё время,
  **92.2 % (2025)** и **95.7 % (2026)**. Тренировочных дней в 90-дневном окне — 52 (~4.0/нед).
- 2026 по **L3o (порядок упражнений)**: последний день вне топ-5 — `2026-10-22`; с `2026-10-23` —
  три дня подряд в топ-5 (малое окно, не вывод об «устойчивости навсегда»). По L1 все 164 дня
  входят в топ-5 (5 сигнатур = весь год), поэтому «дней вне топ-5» там нет.

## §6 Приверженность и её насыщение

- **2026:** L1-приверженность 100 % (164/164) — все дни попадают в 5 имён.
- **L3 (набор упражнений), 2026:** 7 сигнатур, топ-5 = 95.1 %; L3o (порядок) — 8 сигнатур,
  топ-5 = 87.8 %. Разница — **порядок внутри дня**: в основном наборе `4. Тяги` (29 дней)
  17 дней начинаются с тяги, 12 — с подтягиваний; ещё 2 дня — сокращённый набор без подъёма ног.
  Плюс вариация состава: 6 дней «становая без шрагов».
- **90 дней:** 52/52 = 100 % на всех четырёх уровнях — метрика **насыщена**. Её ценность —
  на переходах эр и в «новых» днях, а не в установившемся режиме. Показывать 100 % без
  оговорки — misleading.

## §7 Эры и заявленная программа

**Поле `program` заполнено только в 2015–2018:** 451 день из 1 400 (32.2 %); в 2019–2026 —
**0** (949 дней, 67.8 %). Поэтому «заявленная программа» — не основа витрины, а отдельный
исторический срез (форк PG-F7): 2015–2018 = 460 дней с именем тренировки, 60 различных
наборов имён; топ: «На работе / Общая» (41), «Fitseven базовая / День 1» (37),
«Fitseven базовая / День 2» (32), «Raketa / ноги» (32), «Raketa / грудь» (29).

**Эры v1** — календарные годы (таблица §4) + текущая карточка 90 дней. Смена режима
внутри года (2026) **не** детектируется автоматически: по L3o последний день вне топ-5 —
`2026-10-22`, и лишь с `2026-10-23` идут три дня подряд в топ-5 — этого мало для вывода
об устойчивости; по «шаблонам L3o, встречающимся ≥5 раз», все дни с `2026-05-22` попадают
в семь сигнатур (101 день), но это разметка постфактум, а не формальное правило
(цена форка PG-F4).

## §8 Модуль и фенсы

**Модуль:** `koilog/program_patterns.py` (новый, display-only). API-эскиз (фиксируется
до кода, имена — черновик контракта):

- `day_signature(conn, day, level="name") -> tuple[str, ...]` — L1/L2/L3/L3o, кардио-флаг отдельно;
- `templates(conn, since=None, until=None, level="name", min_coverage=0.9, cap=10) -> list[Template]`;
- `era_table(conn, level="name") -> list[EraRow]` — год: дни, сигнатуры, покрытие, топ;
- `adherence(conn, since, until, templates) -> AdherenceReport` — доля + «новые» дни;
- `cycle(conn, since, until, max_gap=14) -> TransitionReport` — матрица, доля кольца, лаг-7;
- `format_templates/format_eras/format_cycle/format_adherence` — рендер таблиц;
- константы: `SIGNATURE_LEVELS`, `DEFAULT_MIN_COVERAGE = 0.9`, `DEFAULT_CAP = 10`,
  `CYCLE_MAX_GAP = 14`, `CURRENT_WINDOW_DAYS = 90`.

**Фенсы:**

1. `state`/`retrain`/`gate`/`digest`/`score`/`ml` — не импортируют модуль (импорт-фенс тестом,
   как у `muscle_load`/`muscle_share`/`work_arc`).
2. `muscle_load`/`muscle_share`/`work_arc` — не трогаются и модуль их не импортирует:
   PG-100 не считает нагрузку (нет тоннажа/КОИ/долей).
3. Запись в БД запрещена: модуль только читает; витрина — `mode=ro`; живая база до/после —
   **бит-в-бит** (sha256 `6a007568…`).
4. Таксономия/имена — только чтение; `taxonomy.normalize` **не применяется** к именам
   тренировок (иначе «ё»-склейка исказит шаблоны задним числом).
5. Новых решающих порогов нет; `CYCLE_MAX_GAP`/`DEFAULT_CAP` — отображательные.
6. `reset --hard` запрещён; `pre-*` копии базы — по правилу RM-98 (файловый откат).

## §13 Честные пределы

- **Имена тренировок — вендорские метки, а не план тренера.** В 2019–2026 поле `program`
  пустое (67.8 % дней), поэтому «программа» восстанавливается только по меткам дня.
- **Переименование ломает шаблон.** W7/D9 показали, что фид меняет имена; L1-шаблон при
  переименовании распадётся. Поэтому в витрине всегда рядом L2/L3-счётчики (устойчивость).
- **Порядок нестабилен в 30 из 343 наборов** (8.7 %); в текущей эре — один такой набор
  (`4. Тяги`). L3o-вариант намеренно не канон.
- **Приверженность насыщена** в установившемся режиме (90d = 100 %). Метрика диагностична
  на сменах эр, а не в стабильном пятидневном цикле.
- **Авто-детекции смены режима нет** (v1): по L3o 2026 стабилизировался ~2026-05-22, но это
  утверждение получено разметкой «шаблоны с ≥5 повторами», а не формальным правилом.
- **643 дня с >1 сессией**: день «схлопывает» порядок сессий (силовая/кардио), межсессионный

- **Нет оценки качества**: PG-100 не говорит, «хорош» ли сплит, и не сравнивает с нормативами.
- **История неоднородна по частоте**: 2022 — 9 дней; «эра 2022» статистически пуста

- **Никакого ML/кластеризации** в v1: сигнатуры считаются точно, без обучения.
- **Статика/планка** участвуют как упражнения (имена), но не как «мышцы» — это забота PW-99/4.14.

1. **Детерминизм:** один и тот же снимок → байт-в-байт одинаковые таблицы (сортировки явные).
