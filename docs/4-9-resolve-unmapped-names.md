## Изменения

1. **`taxonomy.normalize`: ё→е — ТОЛЬКО в слое сопоставления** (решение N8;
   редакция 2, 24.10.2026). `normalize` в ETL используется и в путях записи
   (`etl` ≈1156 `exercise`, ≈1173 `workout_name`, ≈1315 `report`) — складывать
   ё→е прямо в ней нельзя: перезагрузка слила бы «Жим гантелей лёжа» (535,
   journal) с существующей записью «Жим гантелей лежа» (124: 4 journal +
   120 report) — правка записанных имён, запрещена рамкой.
   **Итоговое решение:** `normalize` складывает ё→е (матчинг: словарь,
   классификация, подсказчик, тест-гейт); для **записи** имени в БД вводится
   `storage_name` (прежнее правило: NFC, схлопывание пробелов, **без** ё→е) —
   все контуры записи идут через него. Записанные имена не меняются; оба
   написания остаются раздельными рядами.
   **Классификация:** «Жим гантелей лёжа» матчится на словарную запись
   «Жим гантелей лежа» (ЖИМ ЛЁЖА) — отдельная запись словаря не нужна.
   **Регресс-тест контракта двух функций:** `normalize('лёжа') ==
   normalize('лежа')`; `storage_name('лёжа') != storage_name('лежа')`; карта
   всех call-site'ов `normalize` в ETL — в отчёт 4.9 (каждый контур:
   запись → `storage_name`, сопоставление → `normalize`).
   По существу: предложенное разделение принято, решение в пользу рамки
   неизменяемости корректное. Числа сверены (124 = 4 journal + 120 report;
   535 journal — совпадают).
2. **`taxonomy.EXERCISE_GROUP` +6 записей** (решение N1=A — только
   классификация):
   - Обратные разведения одной рукой → ДЕЛЬТЫ, absolute
   - Подтягивания → ТЯГА ВЕРТИКАЛЬНАЯ, **TOTAL_BODYWEIGHT**
     (WEIGHT_MODE_OVERRIDE; кластер 39..84 с дробями = тело+добавка; канон
     `taxonomy.py:95-98`, `resolve_bodyweight` в etl)
   - Подъёмы рук в стороны → ДЕЛЬТЫ, absolute
   - Сгибания на бицепс → БИЦЕПС, absolute
   - Тяга гантели в наклоне одной рукой → ТЯГА ГОРИЗОНТАЛЬНАЯ, absolute
   - Шраги → ПЛЕЧИ И ТРАПЕЦИЯ, absolute
     (оговорка: веса 30..68 могут быть суммой пары гантелей — тоннаж x2;
     замером не разрешимо; дефолт absolute по группе, на решения не влияет —
     фенс D11-b).
3. **Подсказчик unmapped (N7)**: в loud-репорт при загрузке ETL добавить топ-3
   ближайших имён словаря (нечёткое сравнение). ТОЛЬКО подсказка для человека,
   без автоприменения (автонечёткий матчинг отклонён — тихая мисклассификация).
   Дополнительно вывести `unknown_groups` в health-ноутбук (замер: имена
   видны потребителю как «НЕ ОПОЗНАН», а unmapped в коде ячеек не упоминается).
4. **Утечка выбросов в групповую витрину (N11-a)**: в
   `health/groups.py::_daily_by_group` (≈173–187) фильтр сейчас только
   `is_warmup/skipped` — добавить `is_outlier=0` (эталон фильтра:
   `stats.py:197/740/1079`). В репорт — diff Е-строк до/после (якорь:
   ОТЖИМАНИЯ 374→354 подхода; тоннаж группы 187 494→161 539).
5. **Источники веса тела (N12)**: добавить «Подтягивания» в
   `BODYWEIGHT_SOURCES` (etl ≈2079–2086) + пересборка. Санити: оценка веса
   тела 2020 = 100.0 кг (`estimate_bodyweight` ≈2101) должна уйти к соседним
   годам (69/78); мода подтягиваний 2019 остаётся 67–68 (гравитронные сеты

6. **Пересборка ETL + честный diff** групповых сумм до/после (N4=A: меняется
