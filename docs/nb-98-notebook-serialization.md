# NB-98 — сериализация ноутбуков: пререг (набросок)

**Статус:** набросок **на гейт**. Кода нет, тестов нет, коммит — только этот файл.
**Заказ:** «сериализация ноутбука» (журнал, Task 123); в репозитории NB-98 упомянут
ровно одной строкой — `docs/4-20-incremental-journal.md:280` («Ноутбуки (NB-98 —
отдельная задача)»). Точной формулировки Task 123 в репозитории нет, поэтому скоуп
ниже **реконструирован по замеру поверхности** и требует подтверждения.

## §1 Замеры (2026-11-01, read-only)

**Файлы.** `koilog.ipynb` — 49 687 B, 11 code + 8 markdown; `koilog-health.ipynb` —
972 962 B, 14 code + 12 markdown. Оба `nbformat 4.5`, оба — крупнейший объект в git
(дальше `etl.py` 146 KB в 6.7 раза меньше).

**Картинки.** В health-ноутбуке 5 `display_data`; base64 в `image/png` = **911 596 B
= 93.7 % файла**; одна ячейка (13) — 721 272 B. В `koilog.ipynb` картинок нет вовсе
(только `stream`).

**Диффы.** `*.ipynb` в `.gitattributes` — текст (`* text=auto eol=lf`, бинарными
помечены только `*.png/*.jpg/*.db`), поэтому base64 идёт в дифф целиком. Ноутбуки
трогали **23 коммита**, суммарно **+3 968 / −2 167** строк; последние: `4.12`
render 73/−137, `4.14` render 165/−84, N-2 render 119/−116.

**Что совпадает с контрактом Jupyter (проверено):**

- байты файла == `json.dumps(nb, indent=1, ensure_ascii=False) + "\n"` — оба
  ноутбука, точное равенство;
- `LF`, без `CRLF`, ровно один хвостовой перевод строки;
- `text` у `stream` — **список строк**, не строка;
- `image/png` — строка base64;
- `execution_count` == порядковый номер code-ячейки (не номер в прогоне):
  в обоих ноутбуках расхождений 0, максимум 11 / 14.

**Что расходится:**

1. **`id` ячеек (nbformat 4.5 требует у всех).** Смешанное присутствие:
   `koilog.ipynb` — 15 ячеек с `id`, **4 без**; `koilog-health.ipynb` — 23 с `id`,
   **3 без**. Драйвер `id` не добавляет (проверено на синтетике: ячейка без `id`
   осталась без `id` после рендера). Любой настоящий Jupyter при открытии и
   сохранении добавит `id` сам → чужой рендер даст дифф на ровном месте.
2. **`execute_result` не сериализуется.** Драйвер перехватывает только
   stdout/stderr/фигуры. Последнее выражение ячейки (`x + 1`) не попадает в вывод —
   в Jupyter на его месте был бы `execute_result` с `text/plain`. То есть
   пере-рендер нашим драйвером **не эквивалентен** прогону в Jupyter.
3. **Порядок выводов.** Фигуры дописываются после потоков, а не по факту
   (ячейка, которая сначала рисует, а потом печатает, покажет текст первым).
4. **`metadata` ноутбуков разные по окружениям:** `venv2 (3.13.3)` против
   `.venv (3.12.4)`; `language_info.version` 3.13.3 / 3.12.4. Драйвер `metadata`
   не трогает (проверено) — то есть расхождение «зашито» в файлы и переживёт
   рендер.
5. **Нулевая тестовая защита.** Ни один тест не касается ни `tools/nb_run.py`, ни
   формы `.ipynb`: в `tests/` ноутбуки упоминаются только в комментариях.

**Что уже хорошо (прибивать, а не чинить):** повторный рендер синтетического
ноутбука даёт **байт-в-байт** тот же файл; при падении ячейки файл **не меняется**
(падение до записи, exit 1); `%-магия` вырезается только при исполнении, в
`source` остаётся как есть; пустой stdout не порождает пустого `stream`.

## §2 Скоуп (предложение)

**Входит:** контракт сериализованной формы (что считается «правильным» `.ipynb`) +
исполняемые пины этого контракта + закрытие расхождений 1–3, если развилки ниже
скажут «да». Всё — в `tools/nb_run.py` и новых тестах, без пере-рендера живых
ноутбуков (кроме финального render-коммита, если изменится форма).

**Не входит:** политика хранения картинок, дисциплина render-коммитов, исполнение
ноутбуков в CI, воспроизводимость **чисел** (они зависят от данных, а не от
сериализации), любые правки `koilog/**`, `data/`, `sql/`.

## §3 Развилки (решение — владельца; цена и риск рядом)

**A. `id` у ячеек.**
- **A0** не трогать: 0 кода; риск — первый же Jupyter добавит `id` и даст дифф,
  `nbformat.validate` на файлах не проходит.
- **A1** драйвер достраивает `id` детерминированно (например,
  `sha1(source)[:8]`, коллизии — суффикс): +~15 строк, тест «id у всех», разовый
  render-коммит на 7 ячеек. Минус: правка `source` меняет `id` → шумный дифф при
  редактировании текста ячейки.
- **A2** понизить `nbformat_minor` до 4.4 (там `id` не требуется): 0 кода кроме
  одной строки в драйвере и разового пере-рендера; `id` перестают быть «частично
  нужными». Минус: уход от формата, который пишет современный Jupyter.
- **Рекомендация: A2** — самый дешёвый способ сделать файл *внутренне
  согласованным*, не изобретая правило генерации `id` (A1 шумит на каждой правке
  текста ячейки). Если владелец хочет «как Jupyter» — A1; учтите, что `id` по
  позиции ячейки ломается при вставке в середину, поэтому в A1 он считается от
  `source` и меняется при каждой правке текста.

**B. `execute_result`.**
- **B0** не реализовывать, зафиксировать ограничением в докстринге драйвера и в
  README: «последнее выражение ячейки не сериализуется». 0 кода.
- **B1** реализовать: компилировать последнее выражение отдельно
  (`ast`-разбор), ловить значение, писать `execute_result` с `text/plain` (для
  `_` / `display()` — отдельные ветки). +40–60 строк, тест на арифметику и на
  `None` (не писать `execute_result` для `print`-ячеек).
- **Рекомендация: B0** в этом юните. Ценность B1 — только «совместимость с
  Jupyter», а ноутбуки запускаются нашим драйвером; цена — `ast`-разбор магии и
  риски ложных `execute_result` выше ценности. Зафиксировать как долг (триггер:
  первая попытка открыть/прогнать ноутбук в настоящем Jupyter).

**C. Порядок выводов (потоки vs фигуры).**
- Замер: смешанных ячеек («печать + график») в `koilog.ipynb` нет, в
  `koilog-health.ipynb` — **4** (15, 23, 24, 25), и во всех четырёх `print` идёт
  раньше построения, поэтому текущий порядок «текст → картинка» **совпадает с
  фактическим**. Расхождение проявится только в будущей ячейке «сначала график,
  потом печать».
- **C0** как есть: текст всегда раньше картинки. 0 кода; фиксируем в контракте как
  принятое ограничение.
- **C1** по факту: перехватывать `plt.show()`/`display` и писать в порядке
  вызовов. +30–50 строк, тест «фигура → печать → фигура» даёт три вывода в
  порядке. Минус: без `plt.show()` порядок всё равно угадывается по времени —
  полумера.
- **Рекомендация: C0** — на существующих данных порядок верный, а C1 покупает
  корректность только для сценария, которого пока нет.

**D. Контракт-тесты (обязательная часть юнита).**
- **D0** синтетический ноутбук во временном каталоге, `KOILOG_ROOT` на него,
  драйвер запускается подпроцессом: форма (`indent=1`/`LF`/хвостовой `\n`/
  `text`-список/`execution_count`=ординал), повторный рендер байт-в-байт, падение
  не пишет файл, `%`-магия не ломает, пустой stdout не даёт `stream`, `metadata`
  не трогается. Только stdlib.
- **D1** фигуры: ячейка с `plt.plot` даёт `display_data` с `image/png` (строка) —
  под `skipUnless(matplotlib)`.
- **D2** байт-пин живых ноутбуков: файл == `json.dumps(..., indent=1) + "\n"` и
  `LF`-только. Дешёвый, ловит «кто-то сохранил ноутбук другим редактором».
- **Рекомендация: D0 + D2 обязательны, D1 — под skip.** Всё — новый файл
  `tests/test_notebook_serialization.py`.

**E. Размер и картинки.**
- **E0** оставить base64 как есть: 0 кода, 0 риска; цена — 93.7 % health-ноутбука
  и нечитаемые диффы рендеров.
- **E1** вынести `image/png` в отдельные файлы (`docs/…/fig-*.png`, `binary` в
  `.gitattributes`), в ноутбуке — ссылка. Минус: ноутбук перестаёт быть
  самодостаточным артефактом, появляется контракт имён и чистка сирот.
- **E2** уменьшить вес (dpi/`bbox_inches`/оптимизация PNG): меняет вид графиков.
- **Рекомендация: E0** в этом юните; E1 — отдельная задача с триггером «дифф
  рендера перестал читаться» (сейчас читается: 165/84 строки на рендер).

**F. `.gitattributes`.**
- **F0** не трогать.
- **F1** пометить `*.ipynb binary` — диффы исчезнут совсем (плохо: теряется
  возможность ревью source-правок).
- **Рекомендация: F0.**

## §4 Тиры приёмки (после решения развилок)

- **Т1** форма: синтетический ноутбук → байты == `json.dumps(indent=1,
  ensure_ascii=False) + "\n"`, `LF`, `text` — список, `execution_count` = ординал.
- **Т2** детерминизм: два прогона подряд → одинаковые байты.
- **Т3** отказ: ячейка падает → файл байт-в-байт прежний, код возврата 1.
- **Т4** магия и пустые потоки: `%matplotlib inline` не ломает прогон и остаётся в
  `source`; `print(end="")`/пустой stdout не порождает `outputs`.
- **Т5** `metadata` не переписывается рендером.
- **Т6** (если A1/A2) `id`: либо у всех ячеек, либо `nbformat_minor` 4.4 и `id`
  ни у кого — «смешанного» состояния нет.
- **Т7** (D1, skip без matplotlib) фигура → `display_data` + `image/png` строка.
- **Т8** (D2) живые ноутбуки: round-trip байт и `LF`-только.

Ожидаемый отпечаток: базовая линия `Ran 975` + число новых тестов (по Т1–Т8 —
ориентировочно +10…+12), скипов не больше прежних, кроме Т7 в чистом клоне.

## §5 Приёмка

1. Отдельный коммит поверх закрытого 4-20; `koilog/**`, `data/`, `sql/` — не
   тронуты (`git diff --stat` по guarded-путям пуст).
2. Полный прогон на якоре и на живой базе; живая база бит-в-бит.
3. Если менялась форма файлов (A1/A2) — render-коммит **отдельно**, с диффом
   «только то, что заявлено» (7 `id` или 2 строки `nbformat_minor`).
4. `tools/nb_run.py` без изменения поведения там, где тесты не просят: контракт
   фиксируется, а не переизобретается.

## §6 Что не входит (явно)

- Политика картинок (E1), уменьшение dpi (E2), `.gitattributes` (F1).
- `execute_result` (B1) — долг с триггером «первый прогон в настоящем Jupyter».
- Исполнение ноутбуков в CI, валидация через `nbformat` (пакета нет в
  зависимостях; контракт проверяется stdlib-пинами).
- Числа в выводах: они зависят от `sql/training.db` и даты, не от сериализации.
