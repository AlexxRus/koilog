**Замер на копиях живой базы** (temp, `DROP` health-таблиц; живая не тронута, 16 таблиц снято):

«журнал разобран, часы ещё нет» (и он **запинован** на exit 0, см. §5.4), случай **B** —

## §4 Развилки и решения (рекомендация — исполнителя, гейт — лида)

### Р1 — предикат «пустой схемы»

| | вариант | цена/риск | рекомендация |
|---|---|---|---|
| A | глобальный: `sets` пуст **и** health нет | digest продолжает врать в случае A (журнал есть, часов нет) — варт не закрыт | нет |
| B | расширить `_open` (нет файла / нет `sets`) | эти случаи уже честно отказываются; ничего не меняет | нет |
| **C** | **per-command источник**: каждая витрина проверяет то, что читает | 3 маленьких предиката, по месту; `_open` не трогается | **да** |

**Решение Р1 = C.** Предикат: «источник пуст» = таблица отсутствует **или** в ней 0 строк.
- `digest` → health = `aw_daily` **и** `load_daily` (оба пусты — health пуст);
- `outliers`, `return` → `sets` (0 строк);
- `check`, `export`, `score` — **не трогаем** (карта §3).

### Р2 — уровень гарды

| | вариант | цена/риск | рекомендация |
|---|---|---|---|
| A | только CLI | карточка `digest` в случае A остаётся с «тренируйся по плану» — варт не закрыт | нет |
| **B** | **гибрид:** CLI — exit-коды и отказы `outliers`/`return`; `digest.py` — честный текст карточки; `state.py:480` не трогается | две точки, зато каждая по своей роли (решение — в state, текст — в digest, отказ среды — в cli) | **да** |
| C | всё в домене (`digest`+`state`) | правит единственный источник правды решений; лишний риск для гейта | нет |

**Решение Р2 = B.** В `digest.py` ветка `normal` при `state.reason == "нет данных"` (или
`day == "?"`) даёт честную рекомендацию вместо «тренируйся по плану»; `state.py:474-486`
(ветка normal / easy) **не трогается**. Как следствие, существующий пин
`test_health_state.py:269` (`reason == "нет данных"`) остаётся зелёным без правки.

### Р3 — судьба врущих витрин `outliers`/`return`

| | вариант | цена/риск | рекомендация |
|---|---|---|---|
| **A** | **exit 1 + одна строка «нет данных: …»** (прецедент `stats`/`weeks`) | несовместимо с «честный ноль», но это и есть правило проекта для «нечего считать» | **да** |
| B | exit 0 + явная строка «нет данных» | ломает правило «недель нет → 1»; три разных нуля в CLI | нет |
| C | `outliers` → 1, `return` → 0 | без причины; хуже A | нет |

**Решение Р3 = A.** `digest` — отдельно: exit 1 **только** если пусто и health, и `sets`
(случай B); если `sets` непуст — карточка остаётся exit 0 (пин §5.4), текст честный (Р2-B).

### Р4 — побочный эффект `load`

| | вариант | цена/риск | рекомендация |
|---|---|---|---|
| A | оставить + README | пустой файл 32 768 B после отказа — мусор в каталоге базы | нет |
| **B** | **preflight источников до `etl.connect`** (прецедент `refresh.py:224-240`) | один `os.path.exists` на каждый источник; поведение отказа не меняется, файла нет | **да** |
| C | писать в temp и переименовывать | дорого, риск потери атомарности/блокировок | нет |

**Решение Р4 = B.** Проверка существования `--journal` и `--report` **до** открытия базы;
сообщение отказа — существующее («файл выгрузки журнала не найден» / отчётный аналог).

## §5 Контракт v1 (что именно меняется)

### 5.1 Предикат

Один приватный хелпер в `cli.py`: «источник пуст» по списку таблиц (нет таблицы **или**
`SELECT 1 … LIMIT 1` пуст). `_open` не меняется. Никаких юнит-меток в коде — ссылка
на этот пререг в докстринге.

### 5.2 Поведение по командам

| команда | источник | условие | поведение v1 |
|---|---|---|---|
| `digest` | health, `sets` | health пуст **и** `sets` пуст | exit 1, одна строка: нет данных, что запустить (`load`, `apple-load`, `health-load`) |
| `digest` | health, `sets` | health пуст, `sets` непуст | exit **0**, карточка; рекомендация — «нет данных» (не «тренируйся по плану») |
| `digest` | health | health непуст | без изменений (регресс-пин) |
| `outliers` | `sets` | 0 строк | exit 1, `нет данных: sets пуст - сначала:  python -m koilog load` |
| `outliers` | `sets` | ≥1 строка | без изменений (в т.ч. «выбросов нет» — это честный ноль) |
| `return` | `sets` | 0 строк | exit 1, одна строка «нет данных: …» (без «возврат к весам: ?») |
| `return` | `sets` | ≥1 строка | без изменений (гейт «нет данных часов» остаётся текстом карточки) |
| `load` | файлы | источника нет | exit 1 **до** создания файла БД |
| `check`/`export`/`score` | — | — | **не трогаются** (карта §3: честные) |

### 5.3 Тексты (фиксируются тестами)

- `digest` (нет данных, health пуст): рекомендация уровня `nodata`
  «нет данных: каналы часов и нагрузка ещё не посчитаны (`apple-load`, `health-load`)»;
  строка состояния — «нет данных», не «штатный план».
- `outliers`/`return`: одна строка в stderr или stdout? — **stdout**, как у `stats`/`weeks`
  (прецедент: эти двое печатают отказ в stdout и возвращают 1).
- `load`: сообщение не меняется, меняется только момент (до создания файла).

### 5.4 Пины, которые обязаны остаться зелёными

| тест | что прибивает | почему жив |
|---|---|---|
| `test_cli.py:458` / `:513` | «выбросов нет» на базе **с** `sets` | предикат срабатывает только на 0 строк |

## §6 Планируемые тесты (приёмка кода, шаг 2)

1. `digest`: пусто всё → exit 1, одна строка, в выводе нет «тренируйся по плану»/«можно по плану».
2. `digest`: `sets` есть, health нет → exit 0, карточка, **нет** «тренируйся по плану», есть «нет данных».
3. `digest`: живой набор (или фикстура с данными) → «можно по плану» сохраняется (регресс).
4. `outliers`: `sets` пуст → exit 1, нет «выбросов нет».
5. `outliers`: `sets` есть, 0 помеченных → exit 0 «выбросов нет» (пин жив).
6. `return`: `sets` пуст → exit 1, нет «возврат к весам: ?».
7. `return`: `sets` есть, health нет → exit 0 + «нет данных часов» (пин жив).
8. `load`: нет базы и нет источников → exit 1 **и файла базы нет** (пин на §2.4).
9. `load`: нормальный прогон — существующие тесты зелёные.
10. Синтетика предиката: таблицы нет / таблица пуста / таблица с 1 строкой — три исхода.
11. Форма отказа: одна строка, без `Traceback` (прецедент `_env_failure`).

**Красные линии приёмки:** полный сьют — без новых падений; дельта — только от новых тестов;
`koilog.ipynb` дифф 0 B; числа PG-100 не меняются.

## §7 Риски и честные пределы

- **`check` — вакуумная истина** («распознано 0 из 0»): классифицирован лидом как честный
  ноль, в юнит **не входит**. Зафиксировано здесь, чтобы решение было прослеживаемым.
- **`export` 0 строк** — валидный ответ (пустая выгрузка), exit 0 сохраняется.
- **Предикат по `COUNT(*)`**: если когда-нибудь появятся «только чужие» строки
  (`is_foreign=1`) при 0 своих, `sets` формально непуст; витрины покажут честные нули
  своих фильтров. В v1 не различаем (нет такой базы); при появлении — отдельный форк.
- **Дубль текста «нет данных»** в `digest` (рекомендация и строка состояния) — осознанно:
  одно и то же сообщение в двух местах карточки допустимо, но тест прибивает оба.
- **`load` preflight** проверяет существование файлов, а не их форму (W7-проверки остаются
  в ETL и срабатывают позже) — момент отказа меняется только для «файла нет».
