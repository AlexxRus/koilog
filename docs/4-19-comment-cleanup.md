# 4.19 — чистка машинных маркеров в комментариях тестов (D8)

**Статус:** выполнено; юнит **tests-only** (плюс этот документ). Маркеры кода
юнита убраны из трёх докстрингов `tests/`, прослеживаемость заменена ссылкой на
документ. Правило `docs/housekeeping.md` §8.3 в силе с 2026-10-29.
**База:** `origin/main` = `4b01807`; клон `gu105` — свежий клон origin.
**Основание:** HK-107, вердикт **D8** (§8.2, кандидаты **P1**; §8.4 — «P1
касается только трёх докстрингов в `tests/`»).

## 1. Фенсы

- Меняются только: `tests/test_health_canon.py`, `tests/test_live_guards.py`,
  `tests/test_stats.py` (P1 из §8.2) плюс три докстринга, найденные при
  исполнении (§2.3: `tests/test_health_groups.py`, `tests/test_stats_recent.py`),
  и этот файл. Всё — только строки докстрингов.
- `koilog/**` не трогается — в том числе `state`, `retrain`, `gate`, `digest`,
  `score`, `ml*`; ни один исполняемый оператор не меняется.
- Живая база — `mode=ro`; полный прогон — в клоне. `data/` и `sql/` в рабочем
  дереве не правятся.
- Инварианты §8.4 не затрагиваются: гвард по-прежнему проверяет **среду**,
  семантика — в самих тестах.

## 3. Доказательство, что изменение — no-op для поведения

1. **Диф.** `git diff` — только строки внутри `"""…"""` блоков и только текст;
   ни одного исполняемого оператора, ни одной сигнатуры, ни одного `assert`.
2. **Прогон в клоне с живым тиром** (копии `data/` и `sql/` в клоне, база
   read-only по смыслу теста — сверена хэшем):

   | Прогон | Футер | Код выхода | Падение |
   |---|---|---|---|
   | до правки | `Ran 943 tests in 224.404s` / `FAILED (failures=1, skipped=1)` | 1 | `test_etl_feed_shape.CanonicalFeedTests.test_canonical_journal_has_no_warnings` |
   | после правки (все 6 докстрингов) | `Ran 943 tests in 223.832s` / `FAILED (failures=1, skipped=1)` | 1 | то же самое |

   Дельта `Ran` — **0**; единственное падение — пин формы канон-фида, то есть
   **D9** (`docs/4-18-feed-format.md`), а не этот юнит. До решения D9 живой тир
   остаётся `1F` — это ожидаемо и названо.
3. **Живая база не изменилась прогоном**: sha256 копии `sql/training.db` до и
   после обоих прогонов — `7e3fa083868810bd5cc45373d977d1e7e18ea20a3750e89a9c20d7895ddc4159`
   (58 028 032 B), совпадает с контролем HK-107 §11.3.
4. **Чистый клон без `data/`/`sql/`** (тир живых данных снимается гвардами):
   до правки `Ran 933 tests in 18.900s` / `OK (skipped=36)`, после правки
   `Ran 933 tests in 19.681s` / `OK (skipped=36)` — оба код выхода 0, дельта
   `Ran` — **0**.

## 4. Приёмка

1. `GU-105` в `tests/` — 0; `Task ` в `tests/` — 0; ссылка на пререг стоит в
   каждом из трёх докстрингов (в `test_live_guards.py` — уже была).
2. Полный прогон: живой тир `Ran 943` / `FAILED (failures=1, skipped=1)` —
   единственное падение это D9-пин; чистый клон `Ran 933` / `OK (skipped=36)`.
   Артефакты — полные логи (`tests_before.log`, `tests_after_live.log`,
   `tests_clean_*.log`) и коды выхода.
3. Диф не выходит за три файла тестов + этот документ.
4. Числа §3 датированы 2026-10-29 и не переписываются задним числом.

## 5. Что этим не решается

- Не трогаются маркеры, которые §8.2 оставил осознанно: `W7`, `D11-b`, `D10`,
  `§…`, `раунд 6` — это ссылки на спеки/инварианты, а не коды задач; 20 таких
  комментариев остаются.
- Не трогаются «замеры-обоснования» (`etl.py:746-749`, `taxonomy.py:219`) и
  директивы инструментов (`# pragma: no cover`, `# type: ignore`, `# noqa`).
- Не решается D9: красный пин формы канон-фида остаётся до вердикта по
  `docs/4-18-feed-format.md`.
- `koilog/**` не правится: если в модулях найдутся коды задач, это отдельный
  tests/`koilog`-юнит с отдельным пререгом.
