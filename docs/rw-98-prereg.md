## §2 Развилки (решение заказчика до кода; канон 4.4)

### Решения R1–R8 (закрыты заказчиком, гейт 2026-11-04)

R1=A (E-тоннаж `Σ E×reps`), R2=A (вес тела года; сдвиг на **соседней** границе
года ≈ **+2.9 %** = 70.0/68.0 — исправлена прежняя оценка 3.9 %), R3=A+D (группа
по умолчанию + селектор упражнения), R4=A (календарная **ISO-неделя**, дельта к
предыдущей неделе с данными, разрывы не шьются, аннотация display-only),
R5=A (без собственного порога дуги), R6 (α = недельная КОИ-полоса ≥ «Очень
тяжёлый», β = **OR** c `acwr_warmup > ACWR_ALERT`; AND вырожден = 0 недель),
R7=A+B (таблица пинится + график не пинится, подсекция после «Абсолютный 1RM»,
health-ноутбук не трогается), R8=A (обвес — соседним docs-коммитом в docs-стадии).

### R1 — числитель показателя

| Вариант | Что | Цена |
|---|---|---|
| **A (реком.)** | **E-тоннаж недели** `Σ E×reps` (`sets.weight` после RM-98) — «в сопоставимых кг» дословно | переиспользует `sets`, ~1 функция, 0 новых констант |

| C | КОИ (интенсивность, безразмерная) | не «работа»: теряет объём, единицы не те |

### R2 — знаменатель и его окна

| Вариант | Что | Цена |
|---|---|---|
| **A (реком.)** | вес тела **года** для всех недель года (`estimate_bodyweight`, единственный честный источник) | 0 новых данных; поправка ≈2.9 % на соседних границах лет (см. §1.1) |
| B | интерполяция между годами → «понедельный» вес | **выдумывает** данные, не проверить (запрет фенса «не изобретать») |
| C | понедельно из сырых `total_bodyweight` кластеров | то же, что уже сводит `estimate_bodyweight`; разрежено и шумно |

Окна знаменателя — отдельная развилка не нужна: период веса тела — год, и он
задан источником. Фиксируется, что «вес тела той недели» = вес тела её года.

### R3 — поверхность

| Вариант | Что | Цена |
|---|---|---|
| **A (реком.)** | **группа** по умолчанию (16 групп, 12–406 нед) | плотно, устойчиво |
| **D (реком., аддитивно к A)** | селектор **упражнения** как в «Графике 1RM» (выпадающий список) | переиспользует существующий селектор; дефолт остаётся группой |
| C | дельта-разбивка (перед/сред/зад) | узко: только группа ДЕЛЬТЫ |

Рекомендация — **A + D**: рендер по группе, опционально упражнение; дельта-разбивка
не нужна (она уже есть в существующих витринах мышц/сводки, а не в дуге).

### R4 — окно дуги (скользящие дельты)

| Вариант | Что | Цена |
|---|---|---|
| **A (реком.)** | неделя **календарная ISO-8601** (`date.isocalendar()` → `ГГГГ-Www`, согласовано с `etl.iso_week_sql` и колонкой `week` в `v_weekly_koi`); дельта = к **предыдущей неделе с данными**, разрывы не шьются (аннотация **display-only** через `gap_warmup`) | переиспользует семантику разрывов ACWR, громкая правда о простое; `%Y-W%W` (`muscle_load.week_key`) даёт W00 на стыке года — не годится |
| B | дельта к ровно-предыдущей календарной неделе (без 0-fill) | то же, но проще; проигрывает в аннотации разрыва |
| C | скользящее среднее дельт (N-шаг) | +параметр N и его обоснование; откладывает суть дуги |

Размыкание «скольжения»: что считать шагом «скользящей дельты» (1 календарная
неделя vs 2 vs rolling) — **эскалация заказчику** вместе с R5/R6 (дуга **и** её шаг
— определение, а не реализация). Рекомендация исполнителя — **1 неделя, по
предыдущей неделе с данными**.

### R5 — порог остановки по весу/объёму (у самой дуги)

«Порог остановки по весу/объёму» — это собственный порог дуги, **отдельный** от
стоп-сигналов R6.

| Вариант | Что | Цена |
|---|---|---|
| **A (реком.)** | **без собственного порога**: дуга — чистый ряд, остановки — только R6 (ACWR/КОИ) | нет новой константы, нет ложного «красного» на росте объёма |
| B | абсолютный: дельта > N кг/кг·нед | нужна константа N (не на чем калибровать: нет исходов «перегруз») |
| C | относительный: дельта > N % к медиане поверхности | та же калибровочная дыра + чувствительность к спокойным неделям |

Причина отклонить B/C по умолчанию: у проекта **нет размеченных исходов
«остановился из-за перегруза»**, на которых калибруется порог (та же логика, что
уже записана в D11: нагрузка — мониторинг, не вход решений). Эскалация: если
заказчик хочет именно «порог по объёму» — нужен его численный заказ.

### R6 — главная пара сигналов-остановок и правило конфликта  *(эскалация)*

Пара: **(a) ACWR gap-aware** (`acwr_warmup > 1.5`, порог уже есть) × **(b) недельная КОИ-полоса**.

- **R6-α — какая КОИ-шкала (эскалация).** Ссылка заказа «граница 0.4 из §2.5»
  ссылается на **пошаговые** полосы, которые срабатывают каждую неделю (§1.7) и
  как стоп мертвы. Значит, стопом может быть только **недельная** шкала
  (`KOI_BANDS_WEEK` = 2/3/4). Варианты порога недельной полосы: **≥3 («Очень
  тяжёлая») — реком.** (68 недель) vs ≥4 («Вы сошли с ума??», 50 недель) vs ≥2
  (Тяжёлая+, 348 недель — горит часто, как 0.4 по-взрослому).

- **R6-β — правило конфликта.** Оба сигнала шумят по-разному, корреляция слабая
  (62/253 положительных дельт садятся на любой стоп). Варианты:
  **OR — реком.** (стоп = любой из пары; «широкий» оверлей, мониторинг) /
  AND (оба сразу; редкий, строгий) / приоритет (ACWR первичен, КОИ поясняет —
  согласуется с существующей логикой digest, где ACWR уже стоит поверх).

Рекомендация целиком: **R6-α = недельная полоса ≥3, R6-β = OR**, но это
**определение заказчика** — эскалация вместе с R4/R5, до написания кода.
