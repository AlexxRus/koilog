# 4.14 — пререг: «Нагрузка по мышцам» и «Свежесть мышц»

**Статус:** решения F1–F7 приняты владельцем 2026-10-25; код не начат.
**База:** `origin/main` = `4ad14e9` (4.10 принят), справочник `koilog/muscles.py`
(131 имя, 17 меток) не меняется. **Референс:** витрины стороннего приложения-аналога.
**До расчёта зафиксировано:** валюта витрин, пул, исключения, режимы, порог
свежести, якорь, границы периодов, тесты. Пост-хок лов запрещён (канон 4.4).

## 1. Валюта и фенсы

- **Кольцо/доли = подходы.** Каждый подход даёт `1/N` каждой из `N` мышц
  упражнения (N — длина `MuscleProfile.muscles`). Одно число на мышцу, оба
  режима, без вменения веса. Сумма долей по 17 меткам = 1.
- **Тоннаж — только в разрезе режима** (`(мышца × iron)` / `(мышца ×
  bodyweight)`), кросс-режимно **не суммируется никогда**. Проценты тоннажа —
  только внутри своего режима.
- **Кросс-режимная агрегация подходов авторизована этим пререгом** (канон
  4.2/4.5 требует отдельного пререга для кросс-режимных сумм). Тоннаж этого
  разрешения не получает.
- **Display-only:** `muscle_load` не входит в решения — `state`, `retrain`,
  `baseline_gate`, `digest.recommend`, `score`, `ml_*` (включая ramp). Любое
  аналитическое использование — отдельный пререг с критерием ±20%.
- Веса участия не вводятся; справочник 4.10 остаётся multi-label.
- **B отклонён:** ~222 из 1 070 «без веса» — железные записи, вменять им вес
  тела неверно; нужны биомеханические коэффициенты (отжимания ≠ 100 % массы),
  которых нет; 246 сетов с `weight = 0` B оставляет нулём; псевдоточность кг.
- Чистый A отклонён: не даёт одного числа на мышцу (кольцо невозможно).

## 2. Пул подходов (общий для обеих витрин)

Пул = все сеты, **кроме**:

1. `is_warmup = 1`;
2. метка «—» (Разминка);
3. кардио — **группа КАРДИО целиком** (включая греблю с её мышечными
   метками), определять по `taxonomy.mode_of(...) is CARDIO`;
4. статика `is_static = 1` (обе Планки — исключение спеки 4.10);
5. `skipped = 1`;
6. `is_outlier = 1`.

Требование «есть вес и повторы» к пулу **не** применяется. Внутри пула:

- **пул подходов** = 18 869;
- **с весом и повторами** (`weight IS NOT NULL AND reps IS NOT NULL`) =
  17 799; разница 1 070 — подходы своего тела и машин без веса/повторов
  (возвращены в пул F3 и участвуют в кольцах и свежести; тоннаж у них 0);
- 246 подходов с записанным `weight = 0` тоже в пуле; тоннаж 0.

Сверка полного состава: 21 017 всего = 17 799 (вес/повторы) + 1 070
(без веса/повторов) + 825 разминка + 779 кардио + 51 статика + 467 skipped +
26 выбросов.

## 3. Режим для разреза тоннажа

Режим берётся из **записанной колонки `sets.weight_mode`**:
`'absolute'` → `iron`, иначе → `bodyweight`. Это не `taxonomy.mode_of`:
`mode_of` относит ABSOLUTE-упражнения групп с режимом «своё тело» (машинные
скручивания) к своему телу, а запись веса у них железная. Тоннаж существует
ровно там, где вес записан, поэтому разрез — по записи.

Контроль: пул `iron 15 444 / bodyweight 3 425`; с весом и повторами
`iron 15 222 / bodyweight 2 577`. Расхождение с `mode_of` — 195 подходов
(ABSOLUTE-скручивания в группах «своё тело»), оно осознанное.

Кросс-режимность (мышца получает оба режима): **8/17** на «с весом и
повторами», **11/17** на пуле. 11-я тройка добавляется подходами своего тела
без веса: квадрицепс, ягодицы, бицепс бедра (приседания/выпады, записанные без
веса). Кольца это не ломает (валюта — подходы), тоннаж — разрез.

## 4. Кольца «Нагрузка по мышцам» (вид A)

- Периоды: **тренировка** (`session_id`), **календарная ISO-неделя**
  (`strftime('%Y-W%W', date)` — как в проекте), **произвольный интервал**
  (`since <= date <= until`, границы включительно).
- Значение мышцы в периоде = `Σ 1/N` по подходам пула, где мышца входит в
  разметку. Доля = значение / число подходов пула периода (сумма долей = 1).
- Пустой период → «нет данных», не нули.
- Проценты — **производная на выводе**; в справочник и вход не возвращаются.
- Рендер: горизонтальные бары, кольцо — опция; подпись «display-only».

## 5. Тоннаж (только внутри режима)

- Для `(мышца × режим)`: `Σ (weight × reps) / N` по подходам пула этого
  режима с весом и повторами.
- Проценты тоннажа — доля внутри режима; **между режимами не складывать**.
- Суммарный тоннаж «с весом и повторами» за всю историю — 5 166 239 кг
  (контроль; разрезы по режимам — производные).
- `weight = 0` или нет веса/повторов → вклад 0; в кольцах такой подход
  по-прежнему считается (это разные валюты).

## 6. Свежесть мышц (вид B)

- **Стимул** = любой подход пула, где мышца входит в разметку. `1/N` к датам
  не применяется: свежесть бинарна по совпадению мышцы.
- **Якорь** = `MAX(date)` базы (сейчас **2026-10-23**), не календарное
  «сегодня»: при якоре 25.10 и пороге 48 ч витрина становится вся зелёной
  (пустой сигнал). В выводе — «свежесть на 2026-10-23».
- `дней = anchor − последний стимул` (в календарных днях).
- **Порог 48 ч** при дневной дискретизации = `дней <= 1`:
  - `0` или `1` → **«восстанавливается»** (жёлтый);
  - `>= 2` → **«восстановлена»** (зелёный).
- Сырое «дней с последнего стимула» печатается **всегда** рядом со статусом:
  длинные хвосты (449/1 781) видны числом, порог их не прячет.
- Нет ни одного стимула за историю → «нет стимула» (сейчас таких нет; косые
  получают стимул 2026-10-22 через подъёмы ног без веса).
- Адаптивный порог отклонён: медиана паузы — свойство частоты практики, не
  физиологии; даёт вечно-зелёные хвосты.

## 9. Тесты (до приёмки)

1. **1/N**: синтетика — упражнение с 2 мышцами, 1 подход → 0.5/0.5; с 3 →
   1/3; сумма долей = 1.
2. **Исключения**: warmup, «—», кардио, статика, skipped, outlier не входят
   ни в кольца, ни в свежесть; подход без веса входит в кольца и свежесть,
   но даёт тоннаж 0; `weight = 0` — так же.
3. **Режим**: разрез тоннажа по `weight_mode`; ABSOLUTE-скручивания в группе
   «своё тело» — iron; кросс-режимной суммы тоннажа не существует
   (структурный тест).
4. **Свежесть**: якорь `MAX(date)`; `дней <= 1` — «восстанавливается»;
   `2` — «восстановлена»; длинный хвост печатается числом; мышца без стимула —
   «нет стимула».
5. **Периоды**: тренировка/ISO-неделя/интервал дают одни и те же подходы на
   одних и тех же границах.
6. **Display-only**: `muscle_load` не импортируется `state`, `retrain`,
   `digest`, `score`, `ml` (import-фенс, как D11-b).
7. **Live-контроль**: 18 869 / 17 799 / 15 222 / 2 577 / 8 / 11 / 55-33-3484 /
   9 жёлтых / 5 по 2 дня / 4 дня у дельт средних.
